# knowledge-gatekeeper

> **把你收藏了却没看的东西，变成你真的会看的东西。**
>
> 别人解决「怎么把视频变成笔记」。
> 我们解决「什么配进笔记库」。

一套**个人知识库的治理层**方法论，架在转化工具之上，管三件事：进什么、怎么攒、怎么不丢。

获取这一层，我们**集成而不实现**：哪些平台能接、能接到哪一步、卡在哪里，
逐条实测后写进了 [`docs/platforms.md`](docs/platforms.md)。

---

## 为什么需要这一层

你收藏过多少东西？

视频、播客、长文——点下收藏的那一刻是真的想看，然后就没有然后了。收藏夹越攒越厚，
每打开一次就多一分愧疚。这不是自律问题：**收藏这个动作只记录了"标题打动了我"，
没有记录"这里面有多少值得留下的东西"。**

把信息源转成笔记的工具也已经很成熟了——`take-notes`、`video2knowledge`、`video-to-notebook`、`weixin-favor-kb`，它们能把视频或文章变成结构化笔记，有的还带 Anki 卡组和时间戳。这一层做得很好，不需要重复造。

但它们有一个共同点：**默认抓到就处理**。没有质量筛选，没有增量账本，没有防丢。

这在头二十篇时看不出问题。攒到两百篇时，问题会集中爆发：

| 症状 | 根因 |
|---|---|
| 库里一半是噪声，且分不清是哪一半 | 没有质量门禁，空洞内容和干货同质入库 |
| 中断一次就得从头跑 | 没有账本，不知道哪些已完成 |
| 某天发现几十页没了 | 未提交的内容被清理掉 |
| 想复习却找不到从哪开始 | 页面没有统一结构，无法系统回顾 |

这些都不是"转化"能解决的，是**治理**问题。本项目只做这一层。

## 三根纵切机制

治理层不是流水线上的某一环，而是贯穿全程的三根支柱。

### 一、四档质量门禁

转写完不能直接成文，必须先通读定档：

| 档 | 判据 | 处置 |
|---|---|---|
| `high` | 可提取的知识量大，方法具体可复用，冗余少 | 完整入库 |
| `medium` | 有可提取的方法，但夹杂冗余 | 只精炼有效部分 |
| `low` | **拆开包装后**没有可复用的知识 | **不入库** |
| `reject` | 与主题无关 | 跳过 |

四条具体判据：

1. **能提取出多少可复用的知识** —— 首要。通读后能否复述出 3 个以上具体、可验证、能上手操作的知识点
2. **讲的是事实方法还是纯观点** —— 有论据有步骤的加分，只有结论和情绪的减分
3. **冗余占比** —— 引流、寒暄、跑题都算冗余，冗余高只影响 high 与 medium 之分
4. **情绪操纵是否替代了实质** —— 用了逆反、恐惧、夸大等手法本身不扣分，只看它有没有替代掉知识

**标题不是判据，只是提示。** 拿到完整转写稿之后就该直接看内容——标题是代理指标，用它推断实质，等于用包装判断实质。有一类内容专门靠"不一致"传播：《你这样刷题，活该考低分》和《这道题的正解思路》，讲的可能是同一套有效解法。把标题一致性当判据，会系统性地误杀前者，理由仅仅是包装不同。

真正该杀的是**包装之下没有东西**：剥掉逆反、夸张、恐吓这层皮，剩下的还是不是知识？

> 分阶段看：**搜索 / 获取层**用标题筛掉不相关的没问题；**收集 / 定档层**必须唯知识论——只看内容，不看包装。

这一步必须逐篇通读，无法自动化。这是它的成本，也正是它的价值——正因为脚本做不了，它才是护城河。

**收藏不等于优质。** 当初收藏只说明标题打动了你。没有门禁的笔记库，两百篇之后就是一堆噪声。

#### 实测：门禁拦掉了多少

这套方法不是理论推演，它已在一个持续运行、积累了两百余篇的知识库上跑了数月。真实账本统计：

| 项 | 数量 | 占比 |
|---|---|---|
| 进入管线的素材 | 93 | 100% |
| 完成转写、进入定档 | 79 | 85% |
| 定档通过，已入库 | 61 | 66% |
| **定档否决，不予入库** | **20** | **21%** |
| 仅有音频、尚未转写 | 12 | 13% |

关键数字是**每四篇转写稿，就有一篇在定档环节被拦下**（20 / 79 ≈ 25%）。

这批内容如果照单全收，会和那 61 篇混在一起，无法区分，也不会再被清理——这正是转化工具单独使用时必然的结局。而由于账本记录了否决结果，它们不会被重复处理。

### 二、单一账本

所有素材的状态、定档、产出路径只记在一处。每完成一步就回写，不做批量补记。

它带来三个能力：

- **断点续跑**——重跑命令就是续跑命令，已完成的自动跳过
- **积压可见**——"已转写但未定档"是一个可查询的队列，随时知道欠了多少篇通读
- **统计可信**——覆盖率、通过率都是账本算出来的，不是估的

唯一的硬约束：**同一批次只允许一个进程写账本**。并发写 JSON 会互相覆盖，这是最容易踩且最难排查的坑。

结构见 [`examples/ledger.schema.json`](examples/ledger.schema.json)。

### 三、防丢闭环

一条血泪规则：**未提交 = 不存在**。

页面一旦生成，当轮结束前必须提交版本库。禁止用 `git clean -fd` / `git reset --hard` 清理工作区——这两条命令曾经一次吃掉 90 页从未提交的内容。

完整的五条硬禁令见 `SKILL.md`。

## 四层横切（流程背景）

治理机制作用的舞台。这一层的工具已经很成熟，**本项目不重复实现，只定义契约**——
哪些平台能接、接到哪一步，见 [`docs/platforms.md`](docs/platforms.md)。

```
① 获取  →  ② 转译  →  ③ 分流审查  →  ④ 呈现
组合工具    语音转文字    四档定档      人看 HTML
                                      AI 看索引
```

| 层 | 治理机制在此层做什么 |
|---|---|
| ① 获取 | 账本记来源与状态；门禁做清单去重 |
| ② 转译 | 账本记转写路径；门禁做失败重试判定；过程文件不落临时目录 |
| ③ 分流审查 | **门禁主战场**：四档定档，账本写结果 |
| ④ 呈现 | 账本记成页与索引位置；门禁做 0 坏链审计；建完即提交 |

呈现层有两个视图，但**不是并列关系**：

- **人看 HTML** 是主产物，逐篇写，遵循十一要素规范
- **AI 看专家索引** 是派生视图，由账本自动聚合，不手工维护

专家索引的价值随规模增长——二十篇时无用，两百篇时是刚需。所以它应当条件启用，而不是标配。

## 页面规范

模板见 [`templates/knowledge_page.html`](templates/knowledge_page.html)，单文件、离线可读、无外部依赖。

**填充完成的成品长什么样**，见 [`examples/sample-page.html`](examples/sample-page.html)——一篇按下面全部要素写成的真实页面，直接用浏览器打开即可阅读。内容为公开技术知识，不含任何受版权保护的素材。

一篇合格的知识页有明确定义，不含糊：

| # | 要素 | # | 要素 |
|---|---|---|---|
| 1 | 顶部返回条 | 7 | 提示 / 警告块 |
| 2 | 标题 + 标签 + 难度 + 元信息 | 8 | 易混点与误区表 |
| 3 | 一句话总结 | 9 | 自测题（折叠答案） |
| 4 | 知识地图 TOC（5-9 节） | 10 | 页脚来源 |
| 5 | 分节正文卡片 | 11 | 笔记组件（可选） |
| 6 | 对比表格 | | |

两条硬纪律：

- **不使用彩色 emoji**（U+1F000 及以上）——各平台渲染不一致，且干扰文本处理。单色符号如 ★ ☆ ✓ ✗ 可用
- **相对路径铁律**——绝对路径会在知识库迁移或换设备时全盘失效

## 配合谁用

层 ① 和层 ② 我们**只做集成，不做实现**——接入哪些平台、怎么接，见
[`docs/platforms.md`](docs/platforms.md)；但**不写下载器**，那部分用现成工具。
按你的工作流，有两种接法：

### 用法一：自己搭管线（SKILL.md 描述的方式）

你手上有转写稿或文章正文，门禁插在**转译后、成文前**。

| 层 | 用什么 |
|---|---|
| ① 获取 ② 转译 | 你熟悉的方案，或按 [`docs/platforms.md`](docs/platforms.md) 接入 |
| ③ 分流审查 ④ 呈现 | **本项目** |

这是门禁最有力的位置——此时内容尚未定型，`medium` 档可以只取有效部分。

### 用法二：配合端到端工具

`take-notes`、`video2knowledge` 这类工具是端到端的：素材直接变成成品笔记，产物是 HTML / Markdown / Anki，**中间不暴露转写稿**。门禁没法插在中间。

此时把门禁插在**成文后、入库前**：判断这篇笔记配不配进你的库。

判据需要从"面向转写稿"调整为"面向成品"：

| 定档判据（转写稿） | 成品笔记上怎么看 |
|---|---|
| 能提取多少可复用的知识 | 通读后能否复述出 3 个以上具体、可验证、能上手的知识点 |
| 讲的是事实方法还是纯观点 | 笔记里有没有论据和步骤，还是只有结论和情绪 |
| 冗余占比 | 篇幅里有多少是铺垫、重复与主题无关的枝节 |
| 情绪操纵是否替代了实质 | 剥掉逆反、夸张、恐吓的包装后，还剩不剩知识 |

标题在此同样不作判据——成品笔记的标题由工具或你自己生成，与原素材标题已经无关，更不该拿它去倒推内容质量。

**注意**：用法二下 `medium` 的处置（只取有效部分）不再成立——笔记已成文，只能整体取舍。此时实际只用得到 `high` 和 `low` 两档。

## 相关工具

本仓库**集成获取，但不实现获取**。下面是各自独立的第三方项目，**我们不维护，也不为其背书**——列出来只为省你搜索的时间。链接可能变动，失效了欢迎开 issue 告知。

### 自己搭管线时（层 ① ②）

| 用途 | 工具 | 说明 |
|---|---|---|
| 下载媒体 | [yt-dlp](https://github.com/yt-dlp/yt-dlp) | 命令行音视频下载。1747 个提取器（2026.06.09 版实测），**逐平台清单见 [`docs/platforms.md`](docs/platforms.md)** |
| 语音转文字 | [faster-whisper](https://github.com/SYSTRAN/faster-whisper) | CTranslate2 加速的 Whisper，本地推理，无 GPU 也能跑 |

### 端到端转化（层 ① 到 ④ 一把做完）

| 工具 | 特点 | 产出 |
|---|---|---|
| [take-notes](https://github.com/davertor/take-notes) | Agent Skill，装进 Claude Code / Codex / Cursor 等宿主即可用 | HTML 笔记，可导出 Markdown 与 Anki |
| [video2knowledge](https://github.com/yc-w-cn/video2knowledge) | Agent Skill，三条本地推理路径（VLM 多模态 / ASR / 音画融合） | 时间戳字幕、知识文档、图文笔记、Anki 卡片 |
| [video-to-notebook](https://github.com/LinZhuoChen/video-to-notebook) | 把整套课程合成为一本笔记本 | 静态站点（教科书 + 概念百科） |
| [weixin-favor-kb](https://github.com/dlv2008/weixin-favor-kb) | 面向微信视频号收藏 | Obsidian 知识库 |

**怎么选**：想尽快跑通，用 `take-notes` 或 `video2knowledge`——它们与本仓库同为 Agent Skill 形态，安装方式一致，装完即可配合本仓库的门禁使用。

## 快速开始

1. 定好知识库根目录，记为 `$KB_ROOT`。

2. 把 `SKILL.md` 放进你的 agent 的 skills 目录：

```bash
mkdir -p ~/.claude/skills/knowledge-gatekeeper
cp SKILL.md ~/.claude/skills/knowledge-gatekeeper/SKILL.md
```

   其他 Agent Skills 宿主同理，把 `SKILL.md` 放到它读取 skills 的目录即可。

3. 让 agent 读这个 skill，从「分流审查」开始接入你现有的转化流程。

4. 自检：让 agent 复述四档判据和账本的六个字段。答得出来就说明加载成功。

> **关于 `config.example.json`**：本仓库**不提供可执行脚本**，因此没有任何代码会去读取它。它是给"打算自己写脚本"的人准备的路径约定——你需要自己实现读取逻辑。只把 SKILL.md 交给 agent 使用的话，可以完全忽略这个文件。

## 什么情况下别用

- **素材总量在 20 条以内**——治理的收益要攒到一定规模才显现
- **你还没有稳定的转化工具**——先把层 ①② 跑通，再谈治理
- **你要的是实时问答**——这是异步沉淀，不是检索增强问答系统

## 已知局限

诚实说明边界，免得你带着错误的期待使用它。

- **没有可运行代码。** 这是方法论加一个 Agent Skill，不是软件。clone 下来没有能直接跑的脚本，得由你的 agent 按 `SKILL.md` 执行。
- **实测数据来自单一知识库。** 文中的 25% 拦截率出自一个运行数月、两百余篇的中文知识库，素材以技术教程为主。**不同领域、不同来源的拦截率会不一样**，别当通用基准看待。
- **四档判据是启发式，不是精确规则。** 它们筛的是明显噪声，不能替代你的判断。拿不准时宁可标 `medium`，也别硬判 `high`。
- **获取只做集成，不做实现。** [`docs/platforms.md`](docs/platforms.md) 是清单与接入约定，
  不是下载器。仓库里没有、也不会有获取相关的代码。
- **平台清单会过期。** 文中的数据取自 `yt-dlp` **2026.06.09** 版实测。提取器随版本增删，
  该版本全库已有 **128 个条目被标注 `CURRENTLY BROKEN`**（其中 TikTok 占 3 个，已在清单中标出）。
  **数字是快照，不是承诺**——复核命令写在清单末尾，请自己跑一遍。
- **未经外部验证。** 截至发布，这套方法只有原作者在用，还没有第二个使用者反馈。
- **用法二的判据是推导的，不是实测的。** 「成文后入库前」那套判据（见上一节）是根据原始判据推导的适配版本，尚未在真实流程中跑过。用了发现不对，欢迎开 issue 纠正。
