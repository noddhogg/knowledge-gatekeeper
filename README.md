# knowledge-pipeline

把「看过就忘的信息源」变成「可检索、可复习、可追问的个人知识库」的一条工程化管线。

这不是一个软件，是一套**方法论 + 可直接使用的规范**。核心产物是一个 `SKILL.md`，把它放进你的 agent 的 skills 目录，agent 就知道该怎么干活了。

---

## 为什么不用「让 AI 总结一下」

一次性 prompt 和管线的差别，不在单次质量，在**能不能攒得住**。

| | 一次性 prompt | 本管线 |
|---|---|---|
| 处理结果 | 一段摘要，看完即弃 | 结构化 HTML 页面，进库可检索 |
| 第二次遇到同一素材 | 重新处理一遍 | 账本里已有记录，直接跳过 |
| 素材质量差 | 照样总结，产出垃圾 | 四档门禁拦截，不入库 |
| 处理到一半中断 | 从头再来 | 断点续跑，已完成的跳过 |
| 攒到 200 篇之后 | 一堆散落文本 | 有索引、有域分类、有 AI 索引 |
| 误删 | 找不回来 | 防丢规则约束，页面建完即提交 |

前三条是质量差距，后三条是**时间尺度上的差距**——一次性 prompt 在第一天和管线差不多，在第 200 天完全不能比。

## 管线长什么样

```
信息源            获取           转写            定档             成页
收藏/文章   →   下载/抓正文  →  语音转文字   →   四档门禁    →   结构化 HTML
                                                  │
                                    ┌─────────────┼─────────────┐
                                  high          medium        low / reject
                                正常入库      只取有效段        不入库
                                                  │
                                                  ↓
                                           ┌──────────────┐
                                           │   个人知识库   │
                                           └───────┬───────┘
                                              ↙         ↘
                                      人看 HTML 页面    AI 看专家索引
```

每个阶段的产出都写进**同一个账本**，账本是整条管线的单一事实源。

## 五个核心设计

### 1. 四档质量门禁（零例外）

转写完不能直接写页，必须先通读定档：

| 档 | 判据 | 处置 |
|---|---|---|
| `high` | 体系化干货，信息密度高，标题与内容一致 | 完整入库 |
| `medium` | 有可提取的方法，但夹杂冗余 | 只精炼有效部分 |
| `low` | 标题党、引流广告、内容空洞 | 不入库 |
| `reject` | 与主题无关 | 跳过 |

判据是具体的四条：**标题与内容是否一致、是否有引流广告、信息密度如何、是否泛娱乐化**。

这一步是整条管线的价值所在。收藏不等于优质，宁缺毋滥——没有门禁的知识库，两百篇之后就是一堆噪声。

### 2. 单一账本

所有素材的状态、定档、产出路径都记在一个 JSON 文件里。它同时承担三个角色：工作队列、断点记录、统计来源。

详见 [`examples/ledger.schema.json`](examples/ledger.schema.json)。

### 3. 断点续跑

批量处理几十上百条时，中断是常态而不是意外。账本里标记为 `done` 的条目自动跳过，重跑命令就是续跑命令。

唯一的硬约束：**同一批次只允许一个进程写账本**。并发写 JSON 会互相覆盖。

### 4. 防丢优先

有一条血泪规则：**未提交 = 不存在**。

页面一旦生成，当轮结束前必须提交版本库。禁止用 `git clean -fd` / `git reset --hard` 清理工作区——这两条命令曾经一次吃掉 90 页从未提交的内容。

完整的五条硬禁令见 `SKILL.md` 的「防丢原则」一节。

### 5. 人机双视图

同一批内容，产出两种视图：

- **人看**：结构化 HTML 页面，带一句话总结、知识地图、易混点、自测题
- **AI 看**：按主题聚合的专家索引，让 agent 一次命中相关页面，不必全文扫描

页面模板见 [`templates/knowledge_page.html`](templates/knowledge_page.html)。

## 快速开始

**第一步**，决定你的知识库根目录，记为 `$KB_ROOT`。

**第二步**，把 `SKILL.md` 放到你的 agent 的 skills 目录下。

```bash
# 以常见的 agent 配置目录为例，按你的实际情况调整
cp SKILL.md ~/.claude/skills/knowledge-pipeline/SKILL.md
```

**第三步**，把 `SKILL.md` 里的路径占位符替换成你的真实路径：

| 占位符 | 含义 |
|---|---|
| `$KB_ROOT` | 知识库根目录 |
| `$LEDGER` | 账本文件路径，建议 `$KB_ROOT/_meta/ledger.json` |
| `$SOURCE_LIST` | 待处理素材清单（CSV / JSON 均可） |

然后让你的 agent 去读这个 skill，从 A 阶段开始跑。

## 什么情况下别用

- **素材总量在 20 条以内**——直接让 AI 总结更快，管线的收益要攒到一定规模才显现
- **你要的是实时问答而不是沉淀**——这是异步沉淀管线，不是检索增强问答系统
- **素材本身是结构化文档**（论文、手册）——直接归档即可，不需要转写和定档

---

## 关于获取层

本仓库**不提供素材获取工具**。

不同平台有不同的获取方式和各自的服务条款，这部分需要你自行实现。管线的 A、B 两个阶段（取清单、获取内容）只定义了输入输出契约，不绑定任何具体平台或工具。
